# 20 - Projets — les unités de travail

Une note par projet, créée depuis `_Template Projet`. **Dossier plat, jamais de sous-dossier par domaine** : le domaine est une propriété.

Nommage : `<CODE> - <Nom>.md`, où `<CODE>` est le code du domaine en majuscules.

## Les quatre sections, dans cet ordre

`## Actions` → `## Décisions` → `## Journal` → `## Pointeurs`

## Ce qui ne va pas dans une fiche

- **Le backlog détaillé.** Il vit dans le substrat canonique. Deux listes de tâches finissent par différer, et on ne sait plus laquelle est à jour.
- **Les comptes rendus.** Une entrée de journal fait dix lignes au maximum, contrôle dur du lint. Au-delà, c'est le substrat canonique qui doit les porter.
- **Les documents.** Un pointeur, jamais un contenu.

Chaque projet actif porte au moins un pointeur canonique — `url_canonique`, `repo` ou `dossier_local`. Contrôle dur : une fiche sans pointeur est une fiche depuis laquelle on ne peut pas rejoindre le travail réel.
